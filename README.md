## 🌐 Overview

Quantum software is rapidly maturing, yet **debugging quantum programs remains a manual, expert-only task**. Quantum circuits expressed in OpenQASM 2.0 are sequences of gate instructions that, when corrupted, produce incorrect quantum states — often silently. This work frames quantum error detection as a **sequence classification problem** and applies state-of-the-art NLP architectures to solve it.

### Key Contributions

```
┌─────────────────────────────────────────────────────────────────────────┐
│  ✅  32,000-sample corpus  —  perfectly balanced, 4-class, zero bias    │
│  ✅  18-operator mutation engine  —  6 per error category               │
│  ✅  Quantum-aware 8-step NLP tokenizer  —  FVAL / IVAL / PI norms      │
│  ✅  BiGRU achieves 82.14% accuracy  —  best single model               │
│  ✅  20 hand-crafted signal features  fused into every model            │
│  ✅  Full ablation study  —  size / embedding / depth / seq-len         │
│  ✅  Gradient saliency + attention heatmaps  —  interpretable           │
│  ✅  Ensemble achieves state-of-the-art  on this benchmark              │
└─────────────────────────────────────────────────────────────────────────┘
```

## ⚡ Error Induction Engine

**18 mutation operators** — 6 per error category — applied round-robin to guarantee sub-type diversity within each class.

### Syntax Errors (6 Operators)

| Operator | Description | Example |
|:---------|:------------|:--------|
| `syn_bad_gate` | Replace valid gate with non-existent name | `h` → `hh` |
| `syn_missing_semicolons` | Remove semicolons from 2 gate lines | `h q[0];` → `h q[0]` |
| `syn_remove_registers` | Strip all `qreg` / `creg` declarations | — |
| `syn_bad_header` | Corrupt OPENQASM version string | `2.0` → `99.9` |
| `syn_bad_bracket` | Truncate register bracket | `q[2]` → `q[` |
| `syn_swap_gate_args` | Swap gate name with qubit argument | `h q[0]` → `q[0] h` |

### Semantic Errors (6 Operators)

| Operator | Description | Example |
|:---------|:------------|:--------|
| `sem_oor_qubit` | Access qubit index beyond register size | `q[0]` → `q[52]` |
| `sem_classical_as_quantum` | Apply gate to classical register | `q[0]` → `c[0]` |
| `sem_duplicate_op` | Insert 3× duplicate gate operations | — |
| `sem_wrong_arity` | Remove second qubit from 2-qubit gate | `cx q[0],q[1]` → `cx q[0]` |
| `sem_wrong_creg_size` | Declare creg too small (size=1) | `creg c[3]` → `creg c[1]` |
| `sem_reuse_qubit` | Apply gates after measure + inflate creg | — |

### Logical Errors (6 Operators)

| Operator | Description | Example |
|:---------|:------------|:--------|
| `log_measure_first` | Move all measurements before gate block | — |
| `log_no_measure` | Remove all measurement instructions | — |
| `log_reversed_gates` | Reverse entire gate sequence | — |
| `log_angle_overflow` | Replace angles with 999.99 or 1e10 | `ry(0.5)` → `ry(999.99)` |
| `log_missing_entangle` | Remove all CX / entanglement gates | — |
| `log_wrong_init` | Insert X+H on every qubit + scramble order | — |

## 🔤 NLP Tokenization Pipeline

Quantum code is treated as a **sequence of linguistic tokens**, normalised through 8 quantum-domain-aware steps:

```
  Raw QASM Code
       │
       ▼
  ① Lowercase        H q[0];  ──────►  h q[0];
  ② Comment Removal  h q[0]; // Hadamard  ──►  h q[0];
  ③ Include Norm     include "qelib1.inc"  ──►  INC_QELIB
  ④ Punct Spacing    q[0],q[1]  ──────►  q [ 0 ] , q [ 1 ]
  ⑤ Arrow Token      ->  ─────────────►  ARROW
  ⑥ Pi Constant      pi/2  ───────────►  PI / 2
  ⑦ Float Angles     1.5708  ─────────►  FVAL
  ⑧ Int Indices      q[0]   ──────────►  q [ IVAL ]
       │
       ▼
  Token Sequence  (max 192 tokens)
```

### Vocabulary Statistics

| Metric | Value |
|:-------|------:|
| Total tokens in corpus | ~2.1M |
| Unique tokens | ~450 |
| Vocabulary size (freq ≥ 2) | ~420 |
| Average sequence length | ~72 tokens |
| Max sequence length | 192 tokens (capped) |
| Special tokens | `<PAD>` (idx 0), `<UNK>` (idx 1) |

### Architecture Overview

```
  Input Token Sequence  +  20 Signal Features
           │                       │
           ▼                       │
  ┌─────────────────┐              │
  │  Token Embedding │              │
  │  (dim = 256)    │              │
  └────────┬────────┘              │
           │                       │
           ▼                       │
  ┌────────────────────────────────┤
  │   Sequence Encoder             │
  │  ┌──────────┐ ┌──────────┐    │
  │  │  LSTM /  │ │Transformer│    │
  │  │   GRU   │ │  Encoder  │    │
  │  └──────────┘ └──────────┘    │
  └────────┬───────────────────────┘
           │
           ▼
  ┌────────────────────────────┐
  │  Pooling (mean + last-real)│
  └────────┬───────────────────┘
           │
           ▼
  ┌────────────────────────────┐   ┌──────────────────┐
  │   Classifier Head (FC)     │ ◄─│  Signal Feature  │
  │   512 → 256 → N_classes    │   │  Projection (64) │
  └────────────────────────────┘   └──────────────────┘
           │
           ▼
   Class Probabilities  [NO_ERROR, SYNTAX, SEMANTIC, LOGICAL]
```

### Model Parameter Counts

| Model | Parameters | Architecture | Bidirectional |
|:------|----------:|:------------|:------------:|
| `LSTM` | ~8.2M | 2-layer LSTM, emb=256, hid=512 | ❌ |
| `BiLSTM` | ~14.1M | 2-layer BiLSTM, emb=256, hid=512 | ✅ |
| `GRU` | ~6.4M | 2-layer GRU, emb=256, hid=512 | ❌ |
| **`BiGRU`** | **~11.2M** | **2-layer BiGRU, emb=256, hid=512** | ✅ |
| `Transformer` | ~18.7M | 8-layer Pre-LN, emb=320, heads=8 | N/A |

### GRU vs LSTM — Head-to-Head

| Aspect | LSTM | GRU |
|:-------|:-----|:----|
| Gates per layer | Forget + Input + Output **(3)** | Update + Reset **(2)** |
| Cell state | Separate `c_t` + hidden `h_t` | Single hidden `h_t` |
| Parameters per layer | ~4× (input × hid) | ~3× (input × hid) |
| Training speed | Baseline | **~20–35% faster** |
| Long sequence handling | Excellent (dual memory) | Good |
| Overfit risk | Moderate | **Lower** |
| Best for this task | ✅ Strong baseline | ✅ **Winner** |

> **Why BiGRU wins on quantum circuits:**
> QASM programs are short sequences (< 192 tokens). GRU's lighter gating design
> prevents overfitting on this moderately-sized dataset. The right-to-left pass in
> BiGRU allows the model to "see" a gate *before* it reads a premature `measure`
> instruction — catching `LOGICAL_ERROR` patterns that unidirectional models miss.

## 🔧 Signal Features

20 hand-crafted features extracted directly from the token sequence, fused into every model's classifier head via a dedicated 64-dim projection layer:

| # | Feature | Type | Catches |
|:-:|:--------|:----:|:--------|
| 0 | `has_bad_gate` | Binary | Syntax: bad gate name |
| 1 | `n_bad_gate` | Ratio | Syntax: density of bad gates |
| 2 | `no_measure` | Binary | Logical: missing measurement |
| 3 | `early_meas` | Binary | Logical: measure before gate |
| 4 | `oor_qubit` | Binary | Semantic: out-of-range qubit |
| 5 | `big_angle` | Binary | Logical: angle overflow (999 / 1e10) |
| 6 | `no_header` | Binary | Syntax: missing OPENQASM header |
| 7 | `no_include` | Binary | Syntax: missing include |
| 8 | `c_as_q` | Binary | Semantic: classical reg as quantum target |
| 9 | `gate_ratio` | Ratio | Overall valid gate density |
| 10 | `seq_len_norm` | Ratio | Normalised token count |
| 11 | `dup_adj` | Ratio | Semantic: adjacent duplicate tokens |
| 12 | `n_fval` | Ratio | Parametric gate density |
| 13 | `n_meas_tok` | Ratio | Measurement token density |
| 14 | `two_q_ratio` | Ratio | 2-qubit gate density |
| 15 | `no_qreg` | Binary | Syntax: missing qubit register |
| 16 | `no_creg` | Binary | Syntax: missing classical register |
| 17 | `has_barrier` | Binary | Barrier instruction present |
| 18 | `high_dup` | Binary | Semantic: >5% adjacent duplicates |
| 19 | `entropy` | Float | Token diversity (entropy proxy) |

> Features are standardized with `sklearn.StandardScaler` before being projected into the 64-dim space.

## 🏋️ Training Configuration

### Hyperparameters

| Hyperparameter | LSTM / GRU / BiLSTM / BiGRU | Transformer |
|:---------------|:---------------------------:|:-----------:|
| Learning rate | `5e-4` | `3e-4` |
| Optimizer | AdamW (β=0.9, 0.999) | AdamW (β=0.9, 0.999) |
| Weight decay | `5e-3` | `5e-3` |
| Epochs (max) | 50 + early stop | 35 + early stop |

| LR schedule | Warmup → Cosine annealing | Warmup → Cosine annealing |
| Loss function | Plain `CrossEntropyLoss` | Plain `CrossEntropyLoss` |
| Gradient clip | norm = 1.0 | norm = 1.0 |
| Grad accumulation | 2 steps | 2 steps |
| Early stopping patience | 12 epochs (after ep 20) | 12 epochs |
| Batch size | 128 | 128 |
| Embedding dim | 256 | 320 |
| Hidden dim | 512 | — |
| FF dim | — | 1280 |
| Attention heads | — | 8 |
| Layers | 2 | 8 |
| Dropout | 0.25 | 0.10 |

> **Why plain CrossEntropyLoss?** The dataset is **perfectly balanced (25.00% per class)**, so class weights = `[1,1,1,1]`. Label smoothing on already-balanced data reduces gradient signal and hurts convergence.

parameter count acts as **implicit regularisation** — the model generalises better
to unseen mutation patterns on the test set.
